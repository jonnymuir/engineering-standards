# k6

Load testing. A tripwire for order-of-magnitude performance regressions, not a benchmark: GitHub
runners are noisy, so absolute numbers vary between runs.

## How it is wired

`.github/workflows/perf.yml` (from [the template](../../template/.github/workflows/perf.yml)) runs
nightly and on demand, never per PR, because it boots the full app and holds load for about 70
seconds. It is not a required check.

1. Build any client bundles, then boot the app in Release on `127.0.0.1:8080` and wait for it.
2. Run `k6 run -e BASE_URL=... -e PROFILE=smoke tests/perf/smoke.js`.
3. Upload `k6-summary.json` as an artifact.

The job fails when a threshold in the script fails.

## Writing the script

`tests/perf/smoke.js` defines scenarios and thresholds. The shape that works:

```js
export const options = {
  scenarios: {
    visitors: { executor: 'ramping-vus', exec: 'visitor', startVUs: 0, stages: ramp(STRESS ? 100 : 20) },
  },
  thresholds: {
    http_req_failed: ['rate<0.01'],                         // under 1% errors
    'http_req_duration{scenario:visitors}': ['p(95)<800'],  // 95th percentile under 800 ms
    checks: ['rate>0.99'],
  },
};
```

- **Read paths only**, unless the app has real per-user identity. Writes against a shared demo
  identity measure the wrong thing.
- **Two profiles:** `smoke` (default, light) and `stress` (ramps up to find the limit), chosen
  with `-e PROFILE=stress` or the workflow's dispatch input.
- **Tag requests by name** (`{ tags: { name: path } }`) so the summary breaks results down per
  page.

## Running it locally

```sh
brew install k6
k6 run -e BASE_URL=http://127.0.0.1:8080 tests/perf/smoke.js
```

Point it only at an instance you own. Never run `stress` against production.
